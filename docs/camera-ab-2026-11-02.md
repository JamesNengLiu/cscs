# 原计划第 7、8 项：本机位置镜头 A/B 与高刷验证

本批提供可回退实验，不修改物理规则。默认仍是 A；在 Esc → 图形与性能 →「位置镜头响应 · A/B」切换，选择保存于本机。`?camera=baseline` / `?camera=responsive` 可临时覆盖当前标签页，单独打开链接不会覆盖保存的偏好。菜单选回 A 即可回退，修改选择后刷新仍保留该选择。

## 实验假设与取舍

- A 保留原来的完整 XYZ 前后物理步插值，位置显示落后一个 60Hz 步长，约 16.7ms；鼠标朝向、反冲显示另走原有路径。
- B 从当前已完成的物理步出发，在玩家副本上用同一碰撞求解器计算最多一个步长的显示预览，按剩余时间取样。每个物理步/权威重基准之间最多计算一次，再次渲染复用结果。
- 仅预览已经消耗的移动输入及正在进行的姿态。新跳跃边沿、新蹲下操作、开火、交互、输入队列和声音不会在预览里执行；副本上的疲劳/速度/姿态不写回真实玩家。暂停、死亡、非操作阶段、预测队列满时禁用预览。
- 直接把旧插值改成无约束的前推并不安全。保存的普通跳复现中，无约束方案的最大首帧上升速度在 120/144Hz 分别约 13.08/19.62 世界单位/秒，原方案约 6.54；因此没有采用它。
- B 对显示位置的追赶速度设限，普通上升/姿态过渡受既有 <10 世界单位/秒的检查保护。仍用实际眼位到显示位置的 BSP sweep 限制穿墙。网络恢复校正最后叠加，不重复平滑；同生命的大位移是否可以平滑仍由原预测恢复策略决定，A 保留原 .5 的重置边界。
- B 的目标是缩短匀速移动时的位置显示滞后。起停、碰撞、起跳/落地的可见过渡仍受约束，不承诺所有动作都快 16.7ms，更不等于实体鼠标到屏幕减少 16.7ms。默认保持 A，主观手感和更多硬件体验后再决定是否推广。

## 回归边界与复测

`tests/fixtures/camera-ab-baseline.json` 在修改前的相机源码上生成，只包含本项目轨迹散列。16 条路线 × 60/120/144/240Hz 的 64 组检查同时验证：A 的显示输出与旧版逐值一致，A/B 的 20 个位置、速度、姿态及疲劳等物理字段散列与旧版一致，眼位未进入实体，B 上升与水平速度未越过既有连续性边界。路线包含起停反向、轮跳、蹲起、空中姿态、低顶、CT 箱沿、落地疲劳和四条坡道上下行。

专项还覆盖副本不改变输入、弹药、冷却及附近玩家，预览缓存、暂停/死亡、重基准/复位、不会制造新跳、设置持久化/存储失败和帧预算计算。实际客户端菜单测试验证 A→B→A、刷新保存、标签页覆盖及 390px 布局。

- `npm run test:camera`：离线轨迹/纯逻辑，不能作为浏览器帧率。
- `npm run test:camera:browser`：顺序执行八个原生 GPU 客户端配置。A/B 各测 headless 原生 rAF、前台原生 rAF、120/144Hz 模拟提交；每个配置均包含平地和 T/CT 斜坡的七组轮跳/起停。脚本不监听游戏端口、不重启现有实例，权威 Game 在离线 IPC 中运行。
- `node tests/run-camera-ab.mjs --report-only`：汇总现有收据，不重新运行浏览器。
- `CAMERA_TEST_MODE=responsive CAMERA_TEST_TAG=camera-b npm run test:feel:browser`：真实客户端主战武器、反冲恢复、AWP 手动开镜及即时反馈回归。
- 同样的环境变量可用于 `test:network:continuity`、`test:player-feedback`；后者可加 `CAMERA_TEST_HEADED=1` 做原生前台九角色渲染压力测试。

原生前台测试以窗口定位到主屏后的实测 rAF 和游戏帧间隔为准，不凭配置名称认定刷新率。测试专用的前台 pointer-lock 替身避免抢占用户实体鼠标，游戏仍走原来的锁定状态分支；headless 回归保留真实浏览器 pointer-lock。模拟时钟只在测试文件导入，保留原生 rAF 的独立样本，模拟 144Hz 不可称为实体 144Hz 显示验收。

## 结果与限制

完整结果见本地忽略的 `artifacts/camera-ab-report.json`、各浏览器收据。帧诊断新增独立的相机 CPU 时间，以及 60/120/144Hz 帧预算、超预算帧、P99 检查。CPU 提交、GPU 最后采样、真实回调间隔分别报告，不推断实体多人吞吐量或完整 CS1.6 一比一复刻。

本轮前已有的人物加载异步测试曾在未修改代码的完整基线中出现一次 `Async asset work did not finish`（100 次 setImmediate 轮询未等到文件 IO）；同一代码单测及完整重跑通过。保留原测试，没有延长等待、放宽断言或将其记为相机回归。

本批不改射击、移动/碰撞、疲劳、输入、后坐力、预测协调、网络时间线、人物骨骼求值及自适应分辨率策略。此前未提交的投掷物粉紫网格修复保持原样，未纳入本次 A/B 提交。没有修改素材或引入 Wasm；实现与自动化阶段未重启服务，用户体验验收时已按要求在原 3001 本机监听范围重启。

原生 120Hz 的游戏平均约 119.93–120.07 FPS；两方案的 P99 均超过 8.33ms，最差场景 1% Low 约 A 96.8 / B 97.1 FPS。帧预算明确报告未达到严格的 120Hz P99 目标；不能把均值接近 120 当成所有帧达标。此次没有据此扩展修改画质或自适应分辨率策略。

实际验证了本机原生 60/120Hz 的客户端运行与 144Hz 的逻辑/渲染提交负载；仍缺实体 144Hz 屏幕、不同设备及真实多人网络下的验收。初次未定位窗口的前台浏览器曾落在 75Hz 节奏，最终矩阵通过显式定位主屏采到原生 120Hz；保留实际采样而非按预设标签认定结果。
