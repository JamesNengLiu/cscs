# AK、M4A1-S、AWP 弹道校准 v2

本轮将三枪接入独立 `cs2-vdata-ballistics-v2`。M4 继续对应现有商店的 M4A1-S，不新增 M4A4，也不改变弹匣、射速、伤害、换弹、购买或移动参数。1.0 与已经修好的输入排序、射击后快切、连续 Q 协议保持原样。

这是以原版 CS2 回放验证并量化误差的浏览器实现，**不是 Valve 内核移植或最新零售版逐值复刻**。反冲随机表、冲量、地面精度恢复和射线倍率有原始数据支持；角度求值使用训练与留出分离的数值近似。未经证明的随机种子映射、移动／腾空额外散布及受击模型仍明确标为未认证。

- [demoparser 原作者固定提交样本](https://github.com/LaihoE/demoparser/blob/4131a4fc02fda291b22421c20e1ca33f149535a7/src/parser/test_demo.dem)：60,601,900 字节，Git blob `e5cc97203262ab36bb756514b02d56eb6bd972a0`，Valve MM、patch13984。它于2024年提交，不能冒充当前版本数据；1,242 条原始射击事件中有641发 AK、128发 M4A1-S、16发 AWP。
- [Valve 二次射击设计说明](https://blog.counter-strike.net/second-shot/)用于核对初始／持续连射恢复设计；[原始 protobuf 定义](https://github.com/SteamTracking/Protobufs/blob/master/csgo/cs_gameevents.proto)用于核对 seed、inaccuracy、recoil_index、spread、mode 等字段。定义中有 Optional Extra，不代表每份 demo 都填了它。

先用项目内纯 JS 的 PBDEMS2 / Snappy / protobuf 窄提取器读取 GE452，再用原作者解析器交叉核对并读取实际实体状态。临时离线模块在本地忽略目录使用，未运行安装脚本、未改系统或游戏依赖。输出去除身份，只保留匿名 player ordinal、版本、时间、枪械和计算字段。

原版的 base angle / velocity 是参考时刻的状态，发间可能保持不变，不能直接拿连续读取的重复值当作“当前镜头角度”。两个样本的 tick 编码／采样阶段也不同；没有把所有 tick 一律除二，或把一次回放的帧归属套到另一份上。

## 已修复的差异

### 反冲表和射线方向

旧版每发用 seed XOR index 重新生成随机数，再直接把任意缩放后的角度加到镜头状态。现在三枪使用连续 Source 风格 RNG 的64项表，全自动枪使用前四发抑制与跨项平滑；平滑保留上一项已经抑制后的幅度，不能换成上一项未抑制值。

原版 AK 首发冲量可逐位匹配；完整30发从零递归计算角速度，最大误差约 `1.15×10⁻⁵ °/s`。M4 的17发轨迹中，第10发发生同人受击；保留并标记此点，其余干净区间冲量在浮点误差范围内。210个小数 index 留出样本支持截断取表，否定四舍五入和邻项插值；其中6条 AK 的时间语义差保留为 censor，没有靠全局 rounding 时间掩盖。

射线按观测到的 `raw aim punch × 2` 构造，摄像机状态不直接乘二。这是本轮 CS2 回放的独立依据，不是把 GoldSrc 的旧双重叠加路径搬过来。射击事件仍在原事务内扣弹并结算命中；本地预测不生成权威伤害或墙面弹孔。

AWP 按实际一段镜／二段镜插值反冲幅度，不能把所有 scoped 状态统一当作同一幅度。六个样本的方向／幅度可匹配，但**从 Valve 射击 seed 选取半自动表项的映射尚未恢复**；浏览器继续使用项目已有的共享反冲 RNG，以保持自身客户端／服务器一致。不能把“反推到了该表项”当作已经独立预测原版 seed。

### 精度、散布与停火恢复

修复总精度向当前姿态基线渐近恢复，替代“基线瞬切＋独立 excess 衰减”。因此蹲下、开镜后仍需要恢复过程；变得更不准确时则立即抬到较大的基线。

恢复时间按衰减前浮点 recoil index 的整数部分选取，然后再对 index 做指数恢复。枪械内部 index 与协议单调 `shotsFired` 完全分开；不会因恢复或换枪重置协议射击序号。步枪恢复延迟采用与样本边界相容的1.1倍射击周期，index 按 `10^(-2·dt)` 恢复。

真实生产 helper 对现代 AK 149个相邻 tick 自由回放：精度最大误差约 `5.54×10⁻⁹`，index 最大误差约 `4.70×10⁻⁷`。历史 AK / M4A1-S / AWP 地面逐步精度最大误差约 `1.89×10⁻⁹ / 2.30×10⁻⁹ / 1.18×10⁻⁸`。旧、新样本的射击 tick 归属分别处理，没有为凑数据改变正式游戏的输入／开火执行顺序。

移动和腾空额外散布仍保留原实验定义及兼容恢复。没有只搬入原版空中恢复时间、却遗漏对应空中基线；这会混用半套模型。现有数据没有足够稳定的原始水平速度来认证线性／四次根移动公式，也不足以校准落地散布和所有 AWP 空中状态。本轮未对这些额外项做原版重写，profile 将它们明确标为未认证。

### 角度响应的工程误差

历史参考的角度衰减8／18不能直接宣称等于 CS2。比较固定顺序、半步拆分和参数可识别性后，采用128Hz数值子步、角度指数8.239、线性17.908、角速度指数4.5的**数据校准近似**。前两项是训练系数，不是声称从 Valve 提取的常数。训练只使用旧 AK 前15发的14个间隔，未使用后续验收点再次拟合。

| 独立验证范围 | 射线误差 RMS | 射线最大误差 |
| --- | ---: | ---: |
| AK 完整30发自由回放 | 0.03994° | 0.09019° |
| M4 受击前后分段、共16个干净点 | 0.05171° | 0.07299° |
| 至少125ms停顿、144条留出 | 0.02964° | 0.09467° |

M4 严格自由17发包含已确认受击，整段最大差异约0.97653°；本轮未校准外部受击模型，不能宣称该整段通过。所有原始误差、censor原因及较差候选均保留。上表是已观测样本的误差，不能外推为任意新版本／场景的保证。

每发重新设定标量基准角、角速度和绝对时间。物理更新、预测重放与渲染采样都从该基准求值，避免60Hz拆步和高刷采样次数改变权威反冲。切到刀／手枪时仍推进残余速度，`keepPunch` 保留同一时钟；晚到射击确认不再加一次冲量。非法或倒退时钟不会让残速回卷。

## 回归与运行边界

- 旧 CS2 v1 的完整 profile JSON SHA保持 `7f55a87e58c34280a2a683c0fa54573c328c773b279da3476d0e09774f564822`。24枪各750 tick，与修改前独立源码 oracle 的全部状态、射击、采样和 RNG 计数哈希完全一致。
- 三枪各360 tick 的移动、跳跃、蹲起与落地物理状态逐值一致。AWP 同 tick 开火／QQ、可靠控制队列阻塞、重复／乱序 ACK、旧快照过滤、真实 feedback 标量复制及自动换弹均有保护测试。
- 60/75/120/144/240Hz数值渲染采样不会改变权威反冲状态；这是纯数值验证，不能当作物理高刷或输入到光子的认证。
- 最终完整 `npm test` **2,351通过，0失败／跳过**；原版生产模块数值对照在最终代码及临时工具清理后再次通过。
- 浏览器使用独立临时 authority 和自有 Chrome，在真实原生地图／人物中实际操作 AK30、M4-S20和三轮合法冷却下的 AWP 开镜→连续 QQ。最终88个同快照时钟的标量与预测重放样本通过；10个实际模块响应 SHA校验、弹药、枪口反馈计数、返回不复镜和 WebGL 检查正常。之前通过的90／89样本收据保留，不混作最终源码的样本数。
- 首轮浏览器夹具因未锁鼠就等待 draw→idle而退出；修复仅涉及测试准备顺序，失败收据保留，未改变正式动画、deploy或射击节奏。

新默认 profile 为 `cs2-vdata-ballistics-v2`。当前3001仍运行旧 v1；新静态文件会按服务器声明选择真实旧算法，不会悄悄混用。只有下一次用户授权重启才加载 v2。未重启、提交或推送，1.0跟踪文件和暂存区保持无差异。
