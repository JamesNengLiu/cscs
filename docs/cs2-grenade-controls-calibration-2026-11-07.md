# CS2 投掷第一批：证据、操作候选与保留基准

本轮在 `codex/cs2` 增加现有 HE、闪光弹、烟雾弹的左键强投、右键弱投和双键中投。此前单一强投保留为比较基准。此次不改变飞行积分、反弹、停止、引爆、烟雾渲染、人物移动或枪械弹道；这些内容分别留待后续轨迹和接触校准。

## 本轮明确采用的可回退候选

- 按键掩码：左键 `1`，右键 `2`，双键 `3`；全部松开为 `0`。只有最终全部松开才提交出手。
- 力度值为强 `1`、中 `0.5`、弱 `0`。本轮速度候选为 `750 × 0.9 × (0.3 + 0.7 × strength)` u/s。这里中等力度不是初速度减半。
- 双键稳定窗口和先后松键容错窗口均暂定 `0.1s`，集中在 CS2 专属控制配置中。这是工程候选，未声称精确等于原版。双键后长期保留单键会切换到该单键力度。
- 保留现有拔销、恢复和出手方向链路。先后松键不额外延迟单键释放。弱投的完整出手高度、动画事件与真实发射缓存采样仍需要原版基准继续校准。
- 服务器根据按钮边沿计算力度；客户端不能提交任意速度。消息仍经过已有可靠顺序和装备屏障；只有成功创建弹体时扣一次库存。
- 预测仅驱动本机持雷和投掷显示，不授权伤害或世界弹体。取消、回合变化和失焦必须结束本机持雷姿态。

## 弱网下按钮边沿聚集

弱网或浏览器长帧可能让按下双键、首个松键和最终松键在同一个服务端 tick 到达。若直接使用收包时间计算上述窗口，原本已稳定的双键会被误判为短按，最终中投可能变成弱投或强投。

本轮协议为按钮边沿携带相对此次 press 的单调经过时间。客户端使用本机单调时钟；服务端在既有 `round/actionId/seq` 校验与顺序屏障内，额外校验该经过时间的有限值、单调性和允许范围，只将其用于双键稳定和先后松键窗口。仍由服务端根据已接受的按钮状态推导最终力度，客户端不能传入最终速度。这使同一组按钮操作在消息分散到达或聚集到达时得到相同的投掷模式。

该字段不回溯实际出手时间，不改写人物位置或速度，不补跑移动 tick，也不改变弹体固定步长。它仅保护投掷控制时窗，不能称为整套 Source 2 subtick 模拟。定向回归应覆盖原始顺序同 tick 批量交付、延迟交付、倒退/非数时间、重复边沿以及切枪取消后迟到的松键。

原版完整按钮时间线、带初始速度的投掷回放尚未建立独立复算链路。这批交付的是有来源区分、可以回退的三种投法与工程基准，不能据此宣布所有轨迹已经与原版逐值一致。

## 工程保留基准

不可变基线为 `46dd5103c692d200d2ae849ad221fb790f94594b`。执行：

```sh
node tools/evaluate-cs2-grenade-controls.mjs
```

该提交是本轮开始时的 HEAD。工具通过 `git show <固定提交>:cs2-grenades.mjs` 和 `git show <固定提交>:public/cs2-grenade-profile.js` 分别载入旧运行时与旧配置，调用旧模块自身的 `createGrenadeRuntime`；并非拿新运行时仅切到 v1 配置作比较。绝对模块 URL 只解决相对 import 定位；旧运行时代码和配置的原始文本各自计算 SHA-256 留在收据中。工具也检查运行时使用的共享数学、规则、计时和烟雾辅助模块与基准提交相同，防止旧 oracle 被新辅助逻辑污染。不额外创建工作树、不绑定端口。它会：

1. 覆盖三类投掷物、站立/移动/蹲姿/空中四种状态和三个俯仰角，共 36 条左键强投轨迹。
2. 将初始位置、速度与随后 90 个 60Hz 时刻逐项对比旧版，共 3,240 个轨迹时刻，包含触地和定时事件。UUID 和新诊断字段不参与物理比较。
3. 对三类物品的三种力度检查候选初速度，共九组。
4. 使用已有真实 CS2 地图的已编译 CPU 碰撞数据及十个静止合成人物，对 0、4、32、64 个活动弹体做旧版→新版→旧版的同输入单步重放，各保留 600 个计时样本，记录 P50/P95/P99 和最大值。
5. 对旧版左投、新版左投和新版双键转换测量预测与消息创建的 CPU 开销，记录每次投掷的消息数量。按钮不变化时不产生持续力度消息。
6. 在测量前后校对相关源码哈希，拒绝把变动中的源码当作同一版本证据。

收据位于忽略目录的 `cpu-and-trajectory-validation.json` 和 `strong-trajectory-baseline.json`。首次执行已通过强投严格相等及九组候选初速度检查；发布前应在所有改动稳定后重跑。后续工具的强投保留门禁明确选择 `CS2_GRENADE_PROFILE_V2` 回退分支，不表示默认 V3 修正后的飞行仍与旧版相同；V3 使用独立的轨迹回放与连续半步性能门禁，见 [后续校准记录](cs2-grenade-trajectory-calibration-2026-11-08.md)。本页性能表保留第一批验收当时的结果。

上述性能值是弹体单步 CPU 微基准，碰撞状态每次复原，未覆盖整局中的持续反弹、烟雾 GPU 或浏览器呈现。预测测试也未计入 DOM 和网络发送开销。它们不能替代前台浏览器帧时间、GPU 耗时、实物鼠标或实体多机局域网测试；这些验收须分别报告。

## 最终代码回归与性能收据

2026-11-07 最终源码固定后，顺序执行以下检查，避免 CPU 微基准与 GPU 回归相互争用：

```sh
npm test
node tools/evaluate-cs2-grenade-controls.mjs
node tests/cs2-grenade-controls-browser.mjs --run
```

- 完整测试：2,411 项通过，零失败、零跳过。包含原版兼容、CS2 弹道保留、移动、AWP 吞弹及连续 Q 的既有用例和新投掷用例。
- 固定旧提交的强投保留：36 条轨迹、3,240 个时刻逐值相等，九组候选初速度检查通过。
- 十个静止合成人物参与的真实地图 CPU 碰撞微基准：4 / 32 / 64 枚弹体单步 P99 分别约为 0.033 / 0.186 / 0.338ms；相对两侧旧版基准平均值的增量分别约为 -0.0004 / +0.0122 / +0.0264ms。
- 实际原生模型浏览器回归：三类投掷物各三档共九种组合，短按右投、两颗闪光恢复期间接续、菜单取消及迟到松键、AWP 开镜开枪后连续 Q 均通过。三类投掷物与全部力度动画在入场前预载；12 次切雷检查和九次投掷动作检查均没有模型/贴图临时请求，投掷动作没有增加 shader program。
- 浏览器使用独立临时 Chrome、Apple M1 Pro Metal 硬件渲染、1920×1080、DPR 1、sharp 画质和完整地图。比较固定旧提交客户端及 viewmodel / 当前客户端及 viewmodel / 固定旧提交客户端及 viewmodel，其他模块及回环权威均使用当前版本。因此这份收据只比较本轮客户端与持枪呈现改动；弹体物理另由上述固定旧模块基准覆盖，并非整套历史构建的性能回放。

每个版本分别采集五秒无弹体持 AK 静止、五秒四枚弹体加 AK 持续射击，共六个测量窗口、1,800 次真实应用帧回调：

| 场景 / 指标 | 旧版第一次 | 新版 | 旧版第二次 |
| --- | ---: | ---: | ---: |
| 无弹体，帧回调 CPU P99 | 5.50ms | 5.40ms | 5.60ms |
| 无弹体，GPU P99 | 10.56ms | 10.33ms | 10.29ms |
| 无弹体，回调间隔 P99 | 18.80ms | 18.90ms | 18.80ms |
| 四枚弹体并射击，帧回调 CPU P99 | 6.80ms | 6.60ms | 6.80ms |
| 四枚弹体并射击，GPU P99 | 10.93ms | 10.50ms | 10.75ms |
| 四枚弹体并射击，回调间隔 P99 | 19.10ms | 19.00ms | 19.10ms |

六个窗口均约 59.98–59.99 次帧回调/秒，没有超过 50ms 的回调间隔或 Long Task。无弹体的 draw calls P99 均为 294，四枚弹体并射击均为 307；这次受控条件下未观察到可重复的帧率或长帧退化。帧回调频率不等于显示器实际呈现帧率；该结果不构成外接 75Hz、内屏 120Hz、实物输入延迟或实体多机局域网认证。

第一批验收当时的浏览器收据为忽略目录内 `browser.json`，记录应用及测试脚本哈希，测量前后完全一致。测试使用随机本机回环端口并在结束后关闭自己创建的 Chrome 与测试权威，未连接、重启或停止持久 3001 服务。当时修改留在 `codex/cs2` 且尚未提交或推送，`main` 和 `v1.0.0` 指向 `0dc0b6958b8f160a11bac21788ef61406217f3d6`；后续服务重启与 Git 发布按用户的单独授权执行。
