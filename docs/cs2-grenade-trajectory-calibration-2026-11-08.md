# CS2 投掷后续批次：轨迹、接触、时序与验证

工作始于 2026-11-07，后续核对跨至 2026-11-08。范围为工程现有 HE、闪光弹、烟雾弹，在 `codex/cs2` 开发。1.0 的 `main`、`v1.0.0` 及经典运行时保持不变；未增加依赖、Wasm、地图资源或原版客户端安装。实现与验证阶段没有执行 Git 发布或重启持久 3001 服务；后续重启与发布均按用户的单独授权执行。

## 版本与边界

默认参数为 `cs2-grenade-pilot-v3`。`CS2_GRENADE_PROFILE_V1` 和 `CS2_GRENADE_PROFILE_V2` 保留为兼容/回退参照，旧积分、反弹和起烟路径仍由旧参数版本选择。它们是 CS2 适配内的历史分支，经典 1.0 文件没有改动。

公开 vdata 固定了投掷武器数据；其周围的出手、积分、接触、引爆时窗仍区分为工程候选和可复算验证。依据及来源见 [证据记录](cs2-grenade-trajectory-evidence-2026-11-07.md)，第一批控制与保留门禁见 [第一批记录](cs2-grenade-controls-calibration-2026-11-07.md)。没有将第三方模拟器实现复制到项目。

## 已实施的后续批次

1. **出手构造**：保留三档速度和自身速度继承，补齐弱/中投的起点下移；较低出手点、前方净空和回退点都经过现有 Source 2 grenade 碰撞通道校验。无障碍强投的初始位置、速度与旧版保持相同。
2. **出手时刻和跳投**：V3 松键后使用可回退的 0.1 秒构造延迟；人物仍按现有 60Hz 求解。跳投缓存来自实际服务器移动步骤，在起跳后 0.1 秒插值采样，0.2 秒有效，最多延后一次等待采样。不会给人物强塞原版某个垂直速度，也不会重跑移动。采样中的 punch 在该步唯一一次武器更新后完成插值。
3. **可靠视角**：松键携带有限、受校验的 `afterInputSeq`。如果没有更新的已执行输入，投掷采用可靠松键视角；旧 datagram 不能覆盖它，更新的命令到达后继续使用实时视角。跳投缓存按采样时刻和实际命令序号选择视角，禁止将后来的视角写回旧采样。该字段不形成新输入屏障，也不修改人物实际角度、位置、后坐力或枪械时钟。
4. **松手后快切**：已经完成拔销并开始释放的投掷，可以在快切后保留一条待出手记录和一枚库存预留。切枪照常响应，成功创建弹体后才扣一次库存；不会改当前枪械的 ammo、lastShot、部署、冷却、换弹、开镜或反冲。未准备完成的取消、显式取消、死亡和回合重置仍清理待投掷状态。
5. **空中运动与反弹**：仅弹体使用 1/128 秒半步，采用重力前后平均速度计算位移。接触后以反射速度继续处理该半步余程；加入高速落地衰减、分量归零、接触间隙及偏置候选。墙角接触次数和长帧补算均有硬上限，没有按一生累计反弹次数把弹体提前停死或引爆。
6. **停止与分类引爆**：HE/闪光按引信截止时刻处理最后不足一个半步的运动，反弹次数不会提前引爆。烟雾保留候选最短引信，等待真实静止和支持面后，在 think 时刻起烟，去掉旧版的 `.95` 地面拖曳及额外排队一拍。V3 弹体保留时间上限为 20 秒安全策略，活动数上限仍为 64。伤害、闪白强度、烟雾体积与烟雾渲染未在本轮调整。
7. **呈现**：V3 弹体快照带实际 `simulatedAt`，CS2 专属插值按弹体时间处理位置，最后静止点也平滑衔接。渲染不预测整条未来轨迹、不新增碰撞射线或渲染通道，显示数量仍限于 32。经典插值模块保持原样。
8. **输入长帧**：按钮时间优先采用有效 DOM 单调事件时间，避免浏览器长帧将不同松键间隔压成同一处理时刻；动画和实际服务器出手时间不会被该时间戳提前。

## 原版公开终点回放

固定参考为 `NC1107/cs2-smoke-solver` 提交 `7ebba5b0443292886d2b2134e67b44736752d82d` 的三份公开实机合成发射报告，每份 60 条，共 180 条。第一组用于核对已公开的运动规则，另两组在参数冻结后作为 held-out 验证，没有按它们逐点调参。三份输入的 SHA-256 在工具及忽略目录收据中固定。

报告给出原生弹体的起点、速度、实际终点和反弹次数；它绕过真人出手。因此可以检验飞行和落点，不能证明真人按键、出生缓存、完整逐 tick 或烟雾 bloom 时序。参考记录的碰撞提取 build 与服务器 build 不同，且未提供原 VPK 哈希，这一限制没有被测试通过消除。

| 全部 180 条 | 固定旧运行时 | V3 |
| --- | ---: | ---: |
| 成功起烟 | 141 | 180 |
| 未产生合法终点 | 39 | 0 |
| 落点误差 ≤3 Source 单位（7.62cm） | 50 | 177 |
| 落点误差 ≤8 Source 单位（20.32cm） | 76 | 179 |
| 成功子集误差中位数 | 5.766u | 0.03093u |

两组 held-out 分别为 58/60、60/60 在 3u 内。旧版的误差分位数只描述成功的 141 条；39 条缺失也保留在完整计数和逐项报告中。

### 未掩盖的参考异常

`top_door` index 11 的原版记录最终在下层 Z=-124.45u、8 次反弹；当前模拟停在上层 Z=115.22u、5 次反弹，误差约 6.22m。原作者自身预测也停在上层、5 次反弹，误差约 243.5u。这仍是未解决的原版参考差异，不能把它当作通过，也不能拿中位数掩盖。

进一步只读诊断确认：

- 固定初态重复回放完全确定；51 种微小位置/速度变化及 float32 舍入实验都没有掉至下层，不能简单归因微小浮点随机分叉。
- 默认五次接触都有明确静态支撑面，最终停点并非凭空悬浮。
- 仅在内存移除 grenadeclip 后，弹体改为接触普通 solid，仍停在上层，误差约 244.4u；全局移除 clip 还会使其它 37 条路线恶化超过 3u。因此不能将异常简单归因 grenadeclip。
- 回放直接注入原始 Pos/Vel，绕过本轮输入、网络与动画，排除了这些新链路解释此重放差异。

缺少原版逐 tick 触点、碰撞掩码、动态状态和原 VPK 身份，仍不能确定原版哪次接触开始分叉。没有为了单一例外修改地图碰撞或其它已验证路线。

## 回归与视觉核对

最终完整测试为 **2,488 项通过，零失败、零跳过**。包含经典兼容、24 枪旧 oracle、AK/M4/AWP 弹道保留、移动与跳跃、AWP 吞弹及连续 Q，以及新增的延迟投掷、跳投、待出手库存、输入视角和插值测试。

独立原生视图 QA 共 18 种组合（三类投掷物 × 三档 × 左右手）通过。idle、拔销开始与投掷后恢复阶段雷体正常可见；hold 的雷体几何存在，实际骨骼和原始 clip 首帧一致，位于镜头身后，握持点最大误差约 1.19μm。因此保留这套导入动画的后引姿态，没有把它强行挪到眼前。这个核对不等于重现完整 retail animation graph。

真实传输最终 20 项通过：一个原生 Chrome 加九个真实 WSS 协议同行，分别运行 QUIC 和 WSS。覆盖可靠控制延迟/合批/重复、QUIC 原始数据报丢失/重复/乱序、300ms 中断、三档持雷与释放、两闪恢复、菜单取消、释放后 Q、AWP 开镜射击加连续 Q、移动跳跃恢复。

额外四条方向检查使用右键弱投，避免左键释放触发已有可靠 `inputCritical` 而掩盖问题。QUIC/WSS 各测一次直接松键、一次松键后 Q：断包期间转头 90°并抬视角，服务器移动视角仍旧，实际创建时的弹体初速度全部严格匹配可靠松键视角，误差为 0 m/s，库存只扣一次。该验证取 `throw` 事件发出时的初态，未拿已经受重力影响的下一帧速度冒充初速度。

一次早期探针在本机拔销尚余 0.2ms 时就按 Q，按既有取消语义被取消。它不是“已经开始投掷后吞雷”的复现；保留失败收据，正式快切用例在服务器和本机均准备完成后操作。WSS 的故障是应用消息故障，不冒充真实 TCP 丢包。QUIC/WSS 的未确认输入在持续采样的小窗口内恢复，位置回拉校验均为 0；原始重组缓存仍在上限内。最后一份 buffer 版本收据也再次通过全部 20 项。

CPU/GPU、真实传输和实体多机验证分开报告；临时自动化服务只绑定随机本机回环端口，结束后关闭自己创建的 Chrome、服务器及同行连接。它们没有重启或加入持久 3001 对局。

## CPU 基准

`benchmark-cs2-grenade-flight.mjs` 使用实际地图 CPU 碰撞和十个静止合成人物，每个测量窗口连续推进八个 60Hz tick，覆盖新弹体的 2/3 半步节奏；每种数量、每个 A/B/A 阶段保留 640 样本。没有使用“每次只跑第一个 tick”的低估方式。

| 活动弹体 | V3 单步 CPU P99 | 相对两侧旧版平均的增量 |
| --- | ---: | ---: |
| 0 | 0.00308ms | -0.00162ms |
| 4 | 0.05900ms | +0.02948ms |
| 32 | 0.35879ms | +0.17594ms |
| 64 | 0.65117ms | +0.27692ms |

4 枚增量 ≤0.3ms、32 枚增量 ≤1ms 的预定工程门槛通过。该 CPU 微基准不是整局 CPU、GPU 或屏幕呈现认证；正式帧时间与网络结果见本轮对应收据。

## 最终硬件帧时间对照

在独立 Chrome、Apple M1 Pro Metal、1920×1080、DPR 1、sharp 画质和完整地图中，对 0/4/32/64 枚弹体分别采集旧客户端/新版/旧客户端，每个窗口五秒，共 12 个窗口、3,600 次应用帧回调。非零数量同时持续按住 AK 开火。服务端均为当前 V3；客户端、viewmodel 与 FX 插值按固定旧提交或当前代码选择，因此 GPU 表比较的是本轮呈现开销，物理的旧/新成本由上面的独立 CPU 基准覆盖。

| 弹体数量 | 两次旧版 GPU P99 | 新版 GPU P99 | 新版帧回调 CPU P99 | 三阶段 draw calls P99 |
| --- | ---: | ---: | ---: | ---: |
| 0 | 10.53 / 10.26ms | 10.53ms | 5.40ms | 294 |
| 4 | 10.94 / 10.63ms | 10.95ms | 6.70ms | 307 |
| 32 | 11.47 / 11.44ms | 11.53ms | 7.00ms | 335 |
| 64 | 11.35 / 11.28ms | 11.66ms | 6.80ms | 335 |

全部窗口为约 59.98–59.99 次回调/秒，没有超过 50ms 的回调间隔；本机受控场景未发现可重复的帧率退化。新增 GPU P99 相对两侧旧值的差异在 max(0.2ms, 5%) 的预定波动门槛内；32 枚窗口 CPU P99 比旧值高约 0.2ms，其它数量持平或较低。它们不是屏幕实际呈现帧率、实体多机、75Hz/120Hz 或实物鼠标延迟认证。

压力核对没有丢弃坏结果：静止样本复用前，一次 64 枚窗口 GPU P99 为 15.58ms，单档复测为 12.78ms，旧版也有明显时长波动。随后发现并消除了静止弹体每帧重复插值/对象分配：首次落地仍平滑衔接，后续位置未变则复用当前点。最终表是该版本再次完整 A/B/A 的结果；不能据此断言此前所有 GPU 波动都只来自这项分配。早期记录和失败探针都保留在忽略目录。

最新硬件收据为 `browser.json`，原生视图收据为 `viewmodel/native-viewmodel-qa.json`，最新传输收据为 `network-final-buffer-browser.json`；各自记录了所测试源码和测试夹具的哈希及作用域。

最拥挤组合还做了独立序列化检查：10 个原生人物、64 枚带 `simulatedAt` 的弹体、32 团填满有界孔洞/爆炸清空信息的烟雾，完整状态为 80,189 bytes，低于 122,880 bytes 的消息上限，余量 42,691 bytes。82 个片段倒序重组成功、拒绝数为 0；该检查只证明字节预算及重组，不是弱网延迟或实体多机吞吐认证。

## 复现入口

在仓库根目录执行，先按 [ASSETS.md](../ASSETS.md) 准备本机地图、模型及依赖。真实传输脚本需要本机 CS2 证书；可先通过安全启动器准备 `.local/cs2/certificate/`，但已有 3001 服务运行时不要额外启动实例。原版终点回放另需将证据文档所列三份固定报告保存为 `evaluate-cs2-grenade-trajectory.mjs` 中 `references` 列出的本地文件名；它们仍在忽略目录，不随 Git 分发。浏览器脚本默认使用 macOS 的 Chrome 安装路径。没有准备这些本机资源时，应先使用脚本的准备检查，而不是将完整浏览器命令当作无素材测试。

```sh
npm test
node tools/evaluate-cs2-grenade-controls.mjs
node tools/evaluate-cs2-grenade-trajectory.mjs
node tools/benchmark-cs2-grenade-flight.mjs
node tests/cs2-grenade-network-browser.mjs --run --peers=9
node tests/cs2-grenade-viewmodel-browser.mjs --run
node tests/cs2-grenade-controls-browser.mjs --run --counts=0,4,32,64
```

工具中的真实地图、原生模型和外部原始报告仍遵循资源隔离规则，放在忽略目录；默认测试不下载地图、第三方实现或依赖。原版逐 tick 采集、动态物体/破坏体、精确跳投 subtick 和精确烟雾 bloom 仍不属于已经认证的部分。
