# CS2 地图剔除、合批和分级加载验证

本轮只迭代独立验证页，入口为 `/cs2-map-benchmark.html?dataset=optimized`。上一轮原贴图光照版 `dataset=textured` 继续作为控制；原 1.0 的受跟踪代码、地图/人物/武器资源和 3001 服务状态不变。没有修改准星、弹道、后坐力、移动、跳跃或联机规则，没有安装全局软件或引入 Wasm。

## 实现与范围

1. **保守 PVS 剔除。** 原图自带 4096 个可见性簇及 VXVS 八叉树。通过项目内 Source 2 Viewer 读取固定资源的元数据，并按 CRC 校验后提取原始可见性表。JS 查询依据[开源格式实现](https://github.com/ValveResourceFormat/ValveResourceFormat/blob/7d9e6c9eb70cb3e6510415ac56e2e1ea2a355836/ValveResourceFormat/Resource/Blocks/VoxelVisibility.cs)独立实现，不是 CS2 客户端源码。把原始三角形分配到保守 4m 三维包围盒；未知/实体内部/地图外相机位置回退为全可见，不猜测隐藏范围。
2. **同材质可见索引合批。** 270种原材质按光照模式组织为363个批次。相机变化时只更新可见索引，避免每帧提交上千个小Mesh。透明层保留原始分区与顺序，不按不透明批次强行合并。位置、法线、切线、两套UV、混合与顶点着色属性逐字节保留；没有简化三角形或地图尺寸。
3. **原生 mip 分级加载。** 保留原始最高1024贴图和4096光照精度。全图先有原生低级mip覆盖，首屏实际可见材质在开放观察前恢复原精度；查询只排加载优先级，不隐藏几何。Alpha/透明层不作遮挡体，其查询使用保守实心三角形。WebGL压缩纹理尺寸升级时重建GPU存储，避免把低精度上传失败误判为已完成。转入新区域时继续分片解压和上传，离屏高精度数据可回退低级mip。
4. **预热与内存。** 材质、地图缓冲、原有9个动画人物及压力特效在加载阶段预热，避免把首次出现的编译开销留到交火阶段。CPU静态属性在上传后释放，保留必要的索引重组数据；没有把GPU内存释放或CPU提交耗时当作真实帧率。该独立页丢失GPU上下文后明确要求刷新，不继续使用已释放的CPU属性假装恢复。

旧贴图包和原素材保持不变；优化包独立生成于 `public/assets/cs2-optimized/`。源码和资源继续隔离，不提交原版/派生素材、截图或收据。

## 验证口径

使用同一 M1 Pro / 32GiB、原生Chrome、1920×1080、DPR=1、渲染比例1及相同T/CT/A/B/全图视角、9人物/程序化透明粒子压力与两分钟巡游。先测空页实际回调，再分别记录CPU提交、GPU查询、帧间隔、加载和内存。

首屏指**首个视角可见内容达到原贴图精度、缓冲/材质预热完毕**。其他区域初次进入的精度恢复等待单独记录，稳态帧率等当前视角恢复相同精度后才采样；不把预览mip的帧率当成完整画质结果。首次区域等待、加载期长任务、首次人物、巡游中的长帧不隐去。

150MiB资源预算包含首入几何、可见性和纹理；累计全图请求及缓存重取另报，不把延后加载当作完整地图资源消失。网络仍为本机回环HTTP，不是局域网/互联网首入保证。RSS合计含共享页重复计数，不是独占内存或显存。120/144Hz仅在实际显示回调达标时验收。

## 复现

已经准备好上轮原贴图包与原始地图/转换器时：

```sh
python3 tools/prepare-cs2-optimized.py
node tools/verify-cs2-optimized.mjs
CS2_BENCH_WIDTH=1920 CS2_BENCH_HEIGHT=1080 \
  node tools/benchmark-cs2-map.mjs --headed --optimized
```

准备程序不下载任何软件或素材，临时可见性导出自动清理。`verify-cs2-optimized.mjs` 对属性逐字节核对，并对每个材质批次的有序顶点三元组集合进行完整比较，以检测遗漏、重复或翻转三角形。

## 实测结果

最终同轮实测设备为 Apple M1 Pro / 32GiB，Chrome 156.0.8078.80，ANGLE Metal；空页回调约75.19Hz。下表均为1920×1080、DPR=1；旧版是本轮重新测的原贴图控制，而非拿上一轮不同系统负载的数据替代。

| 指标 | 原贴图控制 | 优化版 |
| --- | ---: | ---: |
| 首屏完整精度可用，本机HTTP | 5.62s | **3.56s** |
| 第二次刷新重建场景 | 5.71s | **3.56s** |
| T 点平均FPS | 55.8 | **75.0** |
| T 点P99帧间隔 | 27.6ms | **14.1ms** |
| T 点绘制 / 三角形 | 1439 / 332万 | **289 / 139万** |
| 全图压力平均FPS | 43.9 | **75.0** |
| 首次人物/特效阶段最长帧 | 40.1ms | **14.4ms** |
| 压力后GC的JS heap | 668.1MiB | **481.4MiB** |
| 压力结束RSS进程合计 | 3.56GiB | **3.28GiB** |
| 首入地图压缩请求数据 | 约323.0MiB | **约163.5MiB** |

RSS含共享页重复计算，不是地图独占物理内存或完整显存。JS heap减少约28%，T点绘制提交减少约80%、三角形减少约58%。保留4541057个原始三角形；减少的是当帧提交，不是删地图。CPU端仅保留约88.2MiB的源/工作索引，静态属性上传后释放；首次解压所需257.8MiB不是持续保留的CPU几何缓冲。没有采样首入瞬时内存峰值，不能以GC后值代替峰值。

CT/A/B、人物透明层压力均约75FPS。两分钟巡游平均约74.95FPS、P99约14.3ms、最长40.5ms，有**5帧超过25ms、零帧超过50ms**；并非完全没有偶发长帧。几何、纹理对象计数稳定，缓存回退/升级没有持续增加对象数量；短测不等于长期泄漏验证。原显示回调只有约75Hz，不据此宣称120/144Hz通过。

额外用同样全高清条件单测首屏显示与**首次**区域精度恢复过程，没有等待完成后才开始计时：首屏显示最长帧14.3ms；T/CT/A/B/全图切换上传阶段最长帧均≤14.3ms，没有>25ms帧。CT首次精度恢复约2.16s，A约0.51s，B约0.17s，全图约2.42s；期间先展示原生低级mip，细节逐步清晰。不是承诺所有地区瞬时完整加载，也不能把该等待时间从体验成本中去掉。

人物与压力特效约0.73s的准备已计入首入工作，未通过把这部分移出测量来隐去卡顿。首入仍观察到1个81ms主线程加载任务，发生在加载遮罩期间；不是“所有初始化都无阻塞”。各视角恢复原贴图精度后才测稳态，同时另测了上述上传过渡。

**判定：本机60帧稳定性及5秒首屏门槛通过；150MiB首入地图预算尚超约13.5MiB，仍未完全收敛。** 全图漫游会继续读取其他纹理，缓存淘汰后可能重读浏览器缓存；不能把逻辑请求总量当新增网络流量，也不能说完整地图只剩163.5MiB。后续可优先做无损几何传输压缩、进一步缩减首入常驻资源，再做跨设备、真实局域网/低带宽及高刷验证；本轮不自动替换1.0或迁移游戏规则。

## 回归与证据

- `npm test` **1831项通过，零失败/跳过**。新增测试覆盖PVS单元/轴映射、交叠/边界、未知区域回退、非法树与掩码、材质批次范围/损坏数据、16/32位索引边界。
- 逐字节确认位置/法线/切线/UV/混合/着色属性；按材质排序比较完整三角形顶点三元组集合，**4541057个三角形无遗漏、无重复、无翻转**。706套完整mip及临时预览均与原生数据相同，不重新绘制或降低最终贴图精度。
- 在T/CT/A/B/全图及24个出生区位置偏移，共29个视角与控制比较；关闭所有剔除后又比较同样29视角，未发现可见缺面。裁掉左360px诊断HUD后，差异仅极少边缘像素；原始比较表保留，不笼统宣称每个像素绝对相同。
- 在新测试上下文里主动丢失GPU上下文，确认停止渲染并明确提示刷新，没有继续读取已释放的CPU属性而崩溃。静态数据释放只用于独立页，未改动1.0模型或其恢复路径。
- 最终完整测量与首次区域过渡测试的运行源码哈希均与当前文件一致。所有临时浏览器/静态测试夹具正常关闭，错误为空。原3001服务状态保持不变；常驻预览只是本机静态页。
- 离线准备程序端到端重跑后，几何gzip、纹理清单及可见性gzip与测试输入逐字节相同，地图清单内容也相同。临时可见性导出自动删除；清理了本轮冗余位置截图和中间数据，保留固定视角证据、比较表及必要资源。本轮没有新增地图/纹理大包下载或安装新工具。
