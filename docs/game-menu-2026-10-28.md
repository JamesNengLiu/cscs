# 游戏菜单与鼠标灵敏度

日期：2026-10-28。最初基于 `feat/smooth-rendering` 实现，现已纳入 `main`，未改服务端规则。本文保留当时验收快照；后续直接在 `main` 迭代，发布提交以远端 `main` 为准。

## 使用

- 大厅点击“游戏菜单 · 鼠标 / 画质设置”，无需加入房间。
- 对局中按 Esc 打开菜单并释放鼠标；点击“继续游戏”重新捕获鼠标。
- 鼠标灵敏度支持滑条和精确数值，范围 **0.10×–5.00×**，步长 **0.05×**，默认 **1.00×** 与旧版相同。
- 设置即时生效，同时影响水平和垂直转向；“恢复默认灵敏度”仅还原鼠标，不重置画质。
- 本机浏览器 `localStorage['lan-strike-mouse-sensitivity']` 保存倍率字符串；同一浏览器/同一来源地址刷新后保留，不跨地址、浏览器、设备同步。浏览器禁用存储时仍可本次使用，并明确提示刷新将丢失。

## 输入与边界

原始基准为 `0.002 rad / mouse movement pixel`，新公式：

```
yaw   -= movementX × 0.002 × sensitivity
pitch  = clamp(pitch - movementY × 0.002 × sensitivity, -1.45, 1.45)
```

该倍率不是原版 CS 控制台 sensitivity 参数或物理 DPI/eDPI 认证。俯仰上限、后坐力、服务端伤害与散布规则不变。

数值失效/空白时保留上一次有效值，提交时将有限越界值钳制、按步长归一；损坏存储回到默认。输入中的短暂不完整数字不覆盖当前有效灵敏度，失焦后恢复规范格式。

打开菜单立即清空按键、开火和待重放输入，继续发送中性心跳。菜单期间忽略游戏转向/移动/装备/换弹/购买快捷键，但服务器时间继续，不是全局暂停、无敌或掉线。恢复鼠标捕获只能由用户点击触发，不在关闭菜单或按 Esc 后强行自动捕获。

菜单具备 dialog/aria 标签和焦点循环，背景大厅/HUD/预览设置 inert。购买菜单与游戏菜单互斥，购买菜单关闭后回到游戏菜单。未加入时主要按钮是“返回大厅”，连接断开时是“刷新并重新连接”。桌面和390px窄屏均检查实图，无横向溢出。

## 验证

- `npm test` 自动发现 `tests/mouse-settings.test.mjs`：默认兼容、倍率、范围、步长、非法值、存储/恢复、只重置鼠标、拒绝/配额异常。
- `npm run test:menu` 使用临时本机随机端口、真实 Chrome/WebGL 和 WebSocket 对手，检查九组行为：大厅入口与默认、滑条/数字边界、真实刷新持久化、恢复默认、焦点约束、真实鼠标捕获后的双轴倍率、Esc 清输入与服务器继续运行、购买菜单互斥、禁用存储。
- 受控的 `movementX/Y` 事件用于核对实际客户端转向增量，不等于测试物理鼠标 DPI/系统加速度。真实用户点击获取 pointer lock 和真实键盘/鼠标开火同时验证。
- 既有双隔离浏览器对战、购买菜单、下坡浏览器、十连接单渲染器回归通过。测试服务器结束后确认端口关闭；现有3001房间未重启，已打开窗口刷新即可加载。
