# Server-authoritative grenades

`grenades.mjs` is an independent JavaScript implementation, not a C++ translation or an exact GoldSrc physics port. ReGameDLL_CS is a community reverse-engineered server GameDLL with fixes and extensions, not Valve-published Counter-Strike client source; matching a reference rule does not establish complete retail-client fidelity. Its only world geometry dependency is `trace` from `public/shared.js`, which traces the shipped original BSP world and `func_breakable` object brushes. Tests use that real map.

## Integration contract

- `createGrenade(owner, kind, now, secondary=false)` accepts an authoritative living player and server time in seconds. Kinds are exactly `hegrenade`, `flashbang`, and `smokegrenade`. It returns a new projectile with a cryptographically generated unique ID, owner ID, throw-time team, position, velocity, birth/fuse times, and internal simulation fields; invalid identity/team/kind/position/time or a solid eye origin returns `null`. Nonfinite optional aim/recoil/velocity components become zero. Browser positive pitch means up; radians are converted to source pitch degrees before the throw calculation. Position starts at the eye plus a **swept** clearance of up to 16/40 units. The player's finite velocity is added before the safety speed cap. Crouch/standing eye heights come from shared movement.
- The caller validates throw intent, phase, inventory and rate limits, checks `game.projectiles.length < GRENADE_LIMITS.active`, and enqueues the returned projectile. Consume inventory only on an accepted throw. Never deserialize a client projectile, owner, target, damage value, or impact position into this API. The accepted aim and player movement state must already be server state. This module does not register a network or teleport endpoint.
- `secondary` intentionally has the same throw trajectory as primary. At this pinned source, secondary attack is shield operation, not a short/underhand throw. The integrating Game handles a minimum 0.5-second pin preparation, held-left-button pose, release commit, and 0.5-second attack cooldown after a throw. If another grenade of the active kind remains, automatic retirement waits until 0.75 seconds: a real held attack after cooldown starts a fresh pin sequence without redeploying. Otherwise retirement remains at 0.5 seconds. Imported viewmodel pullpin/throw sequences follow the authoritative phase; weapon changes, menu cancellation, death and round reset clear pending preparation. Holding never starts a fuse or changes throw power.
- Call `stepGrenades(game, dt)` **after advancing `game.time`**, with elapsed seconds. `game` supplies `players: Map`, `projectiles`, `smokes`, `emit(event)`, and `damage(player, amount, killer, options)`. Missing projectile/smoke arrays are initialized. It replaces both arrays; snapshots should read the current arrays. Repeating a call at the same server time does not integrate flight twice. Reset these arrays and player flash fields on round reset in the integrating game.
- HE invokes `game.damage` with raw floating-point radial damage and exactly `{kind:'hegrenade', hitgroup:'chest', blast:true, armourRatio:1}`. Only that callback applies HP, armour, kill credit and death. The grenade module never writes HP or armour. `killer` is the current player object found by owner ID, or `null` if disconnected. Throw-time team is retained if the owner disconnects or switches team. Self damage is allowed. Other same-team damage requires **`game.friendlyFire === true`**; default is off. Source-specific friendly damage scaling is not reproduced.
- Every detonation queues `{type:'explosion', id, ownerId, kind, x, y, z}`. There are no embedded player objects, target lists, hit claims, health, armour, inputs or full player-state broadcasts.
- A flash queues `{type:'flash', private:true, id:targetId, amount, duration, fade}`. **The integrating transport must route these events only to the connection whose player ID equals `id`, and must exclude them from the public event batch.** `emit` is only the supplied queue interface, so this standalone module cannot enforce socket delivery. `amount` is normalized peak opacity; `duration` is total remaining visual exposure in seconds; `fade` is its ending fade interval, so the initial hold is `duration - fade`. `flashUntil = game.time + duration`, `flashAmount = amount`, and private `flashFade` carries the fade interval in snapshots; expired fields clear on subsequent steps. Frontend rendering uses the event timing for the hold/fade, not a claim that `flashAmount` decays every tick. Self and team flashes are allowed, independently of HE friendly fire.
- Smoke volumes are `{id,x,y,z,bornAt,endAt,radius}` in `game.smokes`, with server-second timestamps and browser-world distances. Frontend rendering consumes these records. Smoke does not become a solid brush, block HE/flash, or change bullet traces in this module.

## Factual source values and choices

GoldSrc distances/speeds use **40 source units per browser world unit**. Time and damage are not divided by 40. Source Z-up maps to browser Y-up; browser aim direction comes from shared `direction`.

## Explicit approximation and resource limits

The .55/.5 gravity multipliers are factual; the browser acceleration assumes conventional server gravity **800 source units/s²**, producing **11 / 10 browser units/s²**. The inspected DLL retrieves the engine's configurable `sv_gravity` in `regamedll/dlls/game.cpp:268`; it does not define its default there. This module does not use the prototype player's separately tuned shared gravity.

Collision response now also references ReHLDS commit **3d88c1ba3c944d87ef47cce4716a726a19a8b646**, [`rehlds/engine/sv_phys.cpp`](https://github.com/rehlds/ReHLDS/blob/3d88c1ba3c944d87ef47cce4716a726a19a8b646/rehlds/engine/sv_phys.cpp), `SV_ClipVelocity` and `SV_Physics_Bounce`. The JavaScript solver runs at the project's fixed **60 Hz** authoritative rate, carrying fractional time between calls; this is not a claim of retail GoldSrc frame scheduling parity.

The collision clip uses overbounce `2 - friction`: normal restitution is **.3 for HE / .2 for flash and smoke**, without ordinary airborne tangent damping. Components below `.1/40` are zeroed. A floor normal above .7 checks outgoing vertical speed against **full gravity `800/40 * dt`**, then clears vertical speed when grounded. Total outgoing speed below **30/40** stops the grenade. Faster floor contacts make one additional push for `(1 - fraction) * dt * .9`, including touch callbacks but no second clip in that tick. Touch damping **.8** applies only if already grounded. Smoke's grounded think adds **.95** damping every .1 seconds and selects detonation after the fuse and ground contact; ignition occurs at the following think. The BSP tracer's existing separation epsilon is retained without an extra .002 normal nudge. The old .45 restitution, per-impact tangent damping, .25 sleep threshold and four-bump 120 Hz flow have been removed.

Current server player hulls are swept as standing/crouched axis-aligned boxes; player movement within a tick is not interpolated. A projectile already embedded in a brush or a newly overlapping non-owner body is removed without damage rather than teleported out. The tracer has no separate `allSolid` result, so its `startSolid` handling remains a deliberate safety approximation. There is no grenade-to-grenade collision. Transparent breakable touch metadata now selects the source's velocity × -2 branch, but the current map has no such transparent breakable fixture; destructive brush behavior is still unsupported.

Original near-surface explosions trace downward and pull the source away from the surface (`ggrenade.cpp:566–573`, `644–651`, `43–45`, `262–264`). For HE the normal offset is `(100-24)*.6 = 45.6` source units. This implementation does **not** reproduce that relocation; it uses the collision-safe projectile position and small upward lift. This materially changes damage and flash visibility around floors, low cover and corners. HE center-only LOS also lacks CZero's multiple visibility samples (`combat.cpp:171–240`, `282–305`). Breakable objects remain solid; blast damage does not destroy them. No water behavior, wind, moving brush entities, glass material classification, decals, sound propagation, PVS/PAS filtering, source animation, sprite puff dynamics or bot smoke occlusion is reproduced.

The source flash factors are documented above; current shorter timing is an explicit project override. Measured browser exposure remains approximate because of point/box visibility, source relocation differences, server tick timing and simplified overlap/visual-fade state. Original spectator flash forwarding is outside this module; private events must not be indiscriminately broadcast to spectators. Smoke is only a bounded server-authored volume record for approximate frontend rendering.

`GRENADE_LIMITS` exposes the integration budgets: **64 active projectiles**, **32 smoke volumes**, **10-second projectile TTL**, **20-second smoke lifetime**, **50 units/s speed cap**, **.25-second maximum integration per call**. If a queue is overfilled, only its first budgeted entries are considered and later entries are discarded. Admission should be checked before inventory consumption. Duplicate projectile IDs within a tick are discarded. Positions must be finite and within the map's bounds padded by 64 world units; invalid entries and expired records are removed. TTL expiry removes a grenade without a forced explosion or airborne smoke. Huge/nonfinite deltas cannot create unbounded simulation work: nonfinite/negative deltas are no-ops; large finite deltas simulate only the latest .25 s, use server time for fuse/expiry, and do not replay old trajectories. Server stalls therefore sacrifice trajectory fidelity. These budgets are local robustness choices, not CS constants.

## Verification

Run `node --test tests/grenades.test.mjs`. The suite uses Game-like authoritative player maps and a damage callback, with valid original-map player hulls. It verifies throw angle/speed/velocity/fuse and clearance, HE radius and armour delegation, self/team policy, world-wall and object-brush occlusion, flash distance/front/back/pitch/body visibility and private event shape, active-flash preservation and expiry, swept wall/body bounces, airborne fuses, delayed grounded smoke and volume expiry, frame subdivision, repeated-step safety, queue/TTL bounds, and nonfinite input handling. Test-only fixture placement is confined to the test module; no production placement or teleport API was added. Transport privacy, inventory, round resets and frontend visuals require integration validation by the parent.


## 2026-10-29 bounce regression

An independent reference-equation run on the same BSP was recorded before the production change. The controlled smoke fixture at `(-18.4, floor + 3, 22)` with velocity `(0,0,3)` hits the slanted surface at **43/60 s**, exits with vertical/horizontal velocities **1.774509500997 / .764705958084**, stops on the second contact at **62/60 s**, and ignites at **1.6 s**, at Z **24.366019831965**. Production now matches these recorded values within 1e-9. Under the old solver this fixture had five contacts, ignited around 1.95 s and stopped at Z 23.6137. The independent 100 Hz reference stops at Z 24.3786: tick scheduling still affects trajectories.

This is a controlled algorithm/BSP comparison, not a measurement of the user's exact T-exit/A-door bounce lineup in a retail CS1.6 client. Initial throw, player velocity and gravity were already source-based; the corrected difference was collision response and ground/think processing. Smoke coverage remains the existing radius-4, 20-second visual volume approximation.
