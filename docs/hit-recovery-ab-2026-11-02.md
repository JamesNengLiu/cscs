# 原计划第 10 项：受击减速恢复时钟 A/B

本轮以 main `c774e1b` 为基线，先保存源码和恢复曲线，再核对来源、实现候选和回归。A 保持当前已认可的规则；B 只调整恢复时钟，不混入硬着陆反馈、枪械参数或受击镜头调整。默认仍为 A，等待实际体验后再决定是否推广 B。

## 参考口径与范围

参考社区逆向服务端 [ReGameDLL_CS 的固定版本 `4a50c42`，CBasePlayer::PreThink](https://github.com/rehlds/ReGameDLL_CS/blob/4a50c42e85fd3778c2b7d24731c7d30c83bbab01/regamedll/dlls/player.cpp)。接地时，系数每次处理增加 .01，并作用于现有速度；没有按经过秒数恢复，也不把它简单当成移动上限。此为社区服务端参考，不是公开的官方 CS 客户端源码或零售进程实测。

本次选择 **100 次/秒参考处理频率**，把恢复时钟折算为每个接地秒 +1；当前模拟仍固定 60Hz。并不主张所有 CS1.6 运行环境的恢复时间都固定相同。

| 初始系数 | A：当前每秒 +.6 | B：候选每秒 +1 | 100 次/秒参考计时 |
| --- | ---: | ---: | ---: |
| .5 → 1 | .8333 秒 | .5000 秒 | .5000 秒 |
| .65 → 1 | .5833 秒 | .3500 秒 | .3500 秒 |

这些是接地处理累计时间。起跳命令仍在离地及原有超速限制之前执行一次完整命令时长的减速；空中保持原有不恢复、不施加地面减速的行为。低顶阻挡不重复扣减。B 在非常接近 1 时消除浮点余差；A 的算术与旧曲线保持逐值一致。

**保留的控制变量：** .5/.65 初值、武器分类、三维速度门槛、击退、地面摩擦与加速度、速度阻尼的 `dt*60` 指数、起跳顺序、空中规则、跳跃高度/疲劳、碰撞、武器射线/伤害/反冲及全部画面表现。

## 系数恢复与实际跑速分开测量

系数到 1 不等于跑速已恢复。本地 250 source units/s 初始/目标速度、持续前进的隔离工况如下。只注入系数，没有击退；每条命令后仅将 X/Z 放回同一真实平坦 BSP 小块，保留速度、Y、姿态和疲劳，防止撞远处墙壁伪造最低速度。它不是整条地图路线计时。

| 初值 | 指标 | A | B | 独立 100Hz 参考方程 |
| --- | --- | ---: | ---: | ---: |
| .5 | 恢复到目标速度 95% | 1.00s | .70s | .73s |
| .65 | 恢复到目标速度 95% | .75s | .55s | .58s |
| .5 | 最低速度 | 35.92 | 40.28 | 23.49 |
| .65 | 最低速度 | 60.54 | 71.37 | 40.74 |

B 的最低速度仍高于完整 100Hz 参考方程，是保留当前 60Hz 阻尼强度和执行顺序的结果。没有为让曲线看上去更像而顺手修改阻尼频率。因此本轮称为「100Hz 参考恢复时钟」，不宣称整条运动曲线一比一复刻。

另使用实际 `Game.damage`，对 AK、M4、MP5、P90、AWP 和 FAMAS 分别测试单发与按现有射速重复受击；初值分类、击退和血量变化均走原逻辑。重复场景至少覆盖三次武器间隔，避免 AWP 被误算成只有一次命中。完整曲线与汇总保存在忽略的 `artifacts/hit-recovery-evaluation.json`。

## 服务器统一选择与回退

`HIT_RECOVERY_PROFILE` 仅接受以下两个值，未知值启动时报错：

- `baseline`：A，默认。`hitRecoveryVersion=0`，每接地秒 +.6。
- `reference100`：B 候选。`hitRecoveryVersion=1`，每接地秒 +1。

这是整个房间的规则，客户端菜单、URL、输入命令不能独自切换。Game 构造参数为 `hitRecovery`；新生/重生玩家沿用房间选项，重置系数为 1。快照发布房间能力及本机玩家档位，本机预测、协调重放和 A/B 镜头副本读取相同规则；远端显示不需要重复的本机预测标记。健康检查增加档位名称/版本，导出诊断仅增加版本号，不导出整个玩家状态。

新客户端遇到未提供该标记的旧服务，明确使用 A；只刷新现有旧服务上的前端不会突然启用 B。启动 B 后所有参与体验的旧页面均需刷新；不声称旧缓存客户端自动理解候选规则。

以下命令只记录如何选择，不代表本次已重启服务；沿用单实例 3001 和本机监听范围：

```sh
# B 候选；需先停止当前实例，并取得重启授权
HOST=127.0.0.1 PORT=3001 HIT_RECOVERY_PROFILE=reference100 npm start

# 回退 A；同样只运行一个实例
HOST=127.0.0.1 PORT=3001 HIT_RECOVERY_PROFILE=baseline npm start
```

## 验证入口与结果

- `npm run test:hit-recovery`：A 的 60 组旧源码金值；两档恢复曲线；多更新率时钟；未受击速度/物理；源参考计时与保留的阻尼边界；起跳/低顶/空中；命中初值/门槛/击退/反冲；预测/重生/输入防越权；相机副本不写回状态。
- 新增四个渲染频率组：60/120/144/240Hz 下，B 的十六条未受击箱沿/坡阶/轮跳路线与旧金值完全一致；两种位置相机的显示轨迹均保持。
- `npm run test:hit-recovery:evaluate`：离线生成曲线。参考方程是独立的平地、无击退 100×10ms 数值计算，不执行零售客户端。
- `CAMERA_TEST_MODE=baseline npm run test:hit-slowdown:browser` 和 `CAMERA_TEST_MODE=responsive ...`：原生 Chrome / 生产客户端 / 离线 Game IPC。每种相机覆盖 A/B 受击起跳、旧服务兼容及 A/B 接地恢复，共十个场景。接地系数恢复实测约 .8333/.5000 秒；首次预测与同序号权威位置一致，最大原始协调幅度约 .092，保留原 .15 检查门槛，未隐藏或改小诊断值。
- `HIT_RECOVERY_PROFILE=reference100 CAMERA_TEST_MODE=responsive npm run test:feel:browser`：候选 B 的主战武器即时反馈、反冲恢复、FAMAS 三连发及 AWP 快切后手动开镜。
- `HIT_RECOVERY_PROFILE=reference100 npm run test:webtransport`：实际 QUIC/WSS 回退、丢包恢复、可靠投掷物与导出档位校验。

当前服务未重启；本轮按用户授权本地提交，暂不推送。没有增改素材、开启公网、修改图形预算或引入 Wasm。真实多人受击手感仍需 A/B 体验验收。

## 最终回归记录

修改前完整 **1213 项**通过；修改后完整 **1301 通过、0 失败、0 跳过**，新增 88 项。新增测试中 60 项是事先保存的旧移动源码轨迹散列，其余覆盖候选时钟及保护边界。清理无用夹具导入后又独立复测 88 项通过，没有放宽旧版断言。

两种相机的十个原生浏览器 A/B/兼容场景均通过。B 档主战武器 **4 组**即时反馈与 **7 组**武器/模式恢复检查通过；B 档人物命中/步态及九角色 **5 项**通过。另测 B 档原生约 120Hz 七条平地/坡阶轮跳路线通过，最大上升速度约 9.8，保留原 <10 断言。实际 QUIC/WSS **15 项**通过，包含恢复版本重组、客户端档位与导出诊断一致性；传输脚本的软渲染不用于 FPS 结论。

本机 Apple M1 Pro、原生前台 Chrome、1280×800、DPR 1、一视角加九个渲染角色：约 **120.05 FPS**，CPU 帧均值约 **2.12ms**，绘制 **74 次**。这是本机渲染回归采样，不是实体十人联机或所有设备保证。

36 个受保护模块散列不变，包含武器/反冲/弹道/命中盒、预测协调、输入、碰撞求解、相机/模型、投掷物及上一轮高刷预算与视口缩放。`Game.damage`、`shoot`、`step`、`targetRay` 函数体逐字一致；共享移动的 substep/movePlayer 执行部分和客户端完整逐帧循环也逐字一致。受击后的水平恢复差异仅来自版本化 helper；未受击状态与跳跃/疲劳数学未改。

持续命中仍按原射速刷新减速状态。候选主要缩短命中间隙及停火后的恢复，不取消原有受击压制。已保留完整实际命中曲线，不用单次恢复计时推断整段对枪结果。
