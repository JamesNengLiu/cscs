# 第 11／12 项：弱网人物连续性与长帧恢复

2026-11-02，以 `main` 的 `2c35a0e` 为基线。先保留全部原文件及散列、运行 1063 项原回归，再用生产客户端、原生 Chrome、离线 60Hz Game 和受控 IPC 传输复现。没有加入现有房间或重启 3001 服务。

## 已复现的原因

1. `GameConnection` 每帧仅交付最新权威快照时，也丢弃了远端插值需要的中间位置样本。缺样本后原生产配置 HOLD，恢复时播放时间能一次跳到较新的位置。
2. 350ms 上行缺包超过八条输入冗余窗口后，服务器明确跳过十四条过期输入。客户端此时需要接受约 1.35 个游戏单位的权威校正；原 `.5` 距离阈值直接清掉显示偏移，实测单帧反向位移约 1.25。扩大恢复阈值后，下一份正常快照又会按 `.5` 把尚未恢复完的偏移清零，因此必须保留恢复状态。
3. 本机长帧与网络抖动需要分开。150/350ms 主线程忙等实验产生约 .45/.65 的位置校正，但这组基线没有反向位移，不能将所有长帧都称作同一种回拉。客户端原 50ms 帧时间截断保留；本批不补造阻塞期间未采样的输入。

实现过程还验证：若把主线程恢复后积压的每个旧包都用于更新时钟，一次本机阻塞会将插值延迟推到 160ms。最终保留位置样本、以每批最新包更新时钟，并隔离已观测到的本机长帧，避免引入这种额外延迟。

## 局部修改及上限

- `GameConnection` 保留最多 **32 份**待消费位置样本；每帧权威协调、UI 与角色成员同步仍只执行最新快照一次。命中事件和可靠操作确认继续即时交付。溢出只淘汰最旧的显示样本，实际到达计数仍全部记录；断线清理队列。
- `snapshot-buffer.js` 新增有界批量入口。每条样本仍独立校验时间、回合、成员及坐标，时钟/抖动只取该批最新记录；单条 `push` 默认行为保留。超过 **100ms** 的本机帧间隔后，后续 **100ms** 仅保留历史样本、不用旧回调校准时钟；首次有效时钟仍能正常初始化。
- 恢复时播放时间最多按经过时间的 **1.2 倍**追赶，所有角色及 push/sample 共享时间预算。同一帧重复取样、集中到包都不能重复消耗预算。正常有样本时按正常目标播放，不恒定以 1.2 倍移动。
- 仅对可验证的地面运动启用最多 **50ms** 速度外推：要求连续地面样本、方向相近、无蹲起过渡、合理武器速度，整段原 BSP 身体扫掠及终点平地支撑均通过，并避开其他玩家。空中、墙、箱沿、坡阶和不确定状态继续保守处理。
- 已获得两端状态、但间隔超过原 250ms 的缺口，只能在 **500ms** 以内且整段平坦通路安全时连接。检测到未知起跳的疲劳重置会拒绝连接，不能将漏掉的跳跃替换成贴地直线。死亡、换生命、换回合、显式传送及过大间隔始终重置历史。
- 本机大校正仅在同一生命、快照明显延迟或服务器明确跳过输入时，允许最多 **2 个游戏单位**的恢复显示偏移；普通路径仍使用原 `.5` 阈值与原指数衰减。大偏移恢复期间限速衰减并跨后续正常快照保留状态，收敛后回到原路径。超过额度的大位移仍直接校正；身份变化不能取得额外恢复额度，跨回合/死亡按原路径清理，不积累无限镜头偏移。原相机的 BSP 眼位限制继续生效。
- 诊断增加待消费显示样本数、溢出数、时钟恢复及播放追赶信息，并可导出恢复状态布尔值；仍不导出玩家身份或整份游戏状态。原始权威校正幅度没有被改小或隐藏。

这些参数只控制客户端显示与时钟。没有提高服务器补步速度，没有重发、补执行或伪造过期动作，也没有启用原版 CS 引擎或 Wasm。

## 前后复现数据

原生 Chrome / Apple M1 Pro / 1280×800，实际项目地图、模型、相机和 Game；主线程忙等与包缺口由测试夹具控制。下面为同脚本基线及最终复测，事件到帧相位仍有差异，不是实体 Wi-Fi 的统计认证。单位为内部游戏单位，不是认证物理米。

停帧计数包含初始化与人物真实转向附近的零位移帧，不应直接换算为精确网络冻结时长。各次复测保留独立收据，不以单次统计声称所有弱网条件都已消除停顿。

上行场景原始权威校正仍约 **1.33**，并没有被“补跑”抹平；改善的是恢复呈现。150/350ms 人为长帧仍真实存在，最终均未观察到反向位移，恢复后的插值延迟约 **71/68ms**。不能把本批解释为消除了所有长任务或物理网络延迟。

增加了斜坡轮跳中 150ms 主线程忙等的真实客户端场景：眼位全程在原 BSP 实体外，包含长帧在内的最大上升速度约 **6.53**，通过原 **10** 的断言。没有降低镜头/碰撞断言来容纳新行为。
