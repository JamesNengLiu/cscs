# 流畅度优化验收（不引入 Wasm）

日期：2026-10-28。工程版本仍为 v0.5；功能分支 `feat/smooth-rendering`，基于人物版本。本文记录性能阶段的验收快照（313项）；后续合并菜单后的提交前测试为318项。代码发布提交以远端功能分支为准，不代表已合并main。

## 目标与边界

降低浏览器主线程动画、重复 UI 更新和不必要资源保留的开销，减少远端人物显示顿挫；为 GPU 受限设备提供有证据的分辨率调节。

不改地图比例、BSP 几何/碰撞、权威移动/伤害、枪械/购买/经济规则，不增加 Wasm/Worker 依赖，不以删人物/贴图/碰撞换性能。保留原来的世界层与独立第一人称深度 pass。

## 已实施

### GPU 刚性骨骼蒙皮

- 人物、第三人称枪、第一人称武器/手臂统一使用 `public/rigid-skinning.js`。CPU 继续按源动画计算骨骼姿态；顶点变换交给 WebGL 2 顶点着色器。
- 每个模型实例使用独立的 4×骨骼数 RGBA32F 调色板纹理。每帧只更新骨骼矩阵，不再在 CPU 逐顶点变换位置/法线和上传整份顶点缓冲。
- MDLv10 的位置骨索引与法线骨索引分别保留，原始身体/定制头、UV、skin/bodypart、九向混合、武器骨骼合并和枪口附件仍使用原数据。
- shader 复用不绑定具体骨骼数，不使用可能超出低端 uniform 上限的 128 个 mat4 数组。保留 `{skinning:'cpu'}` 作为程序测试参考，不新增游戏作弊接口。
- 世界人物继续禁用基于静态源顶点包围体的自动剔除；GPU 蒙皮后源顶点不等于动画姿态，不能直接打开剔除导致人物消失。

### 主循环、UI 与显示

- 缓存 DOM 引用；HUD 文本/部分样式仅值变化时写入。
- 战绩表隐藏时不建表；Tab 打开后只在阵营/姓名/状态/战绩变化时重建。
- 小地图最高 30 次/秒，速度说明最高 10 次/秒；输入、相机和固定 60Hz 预测不降频。
- 远端位置使用与帧率无关的指数平滑，yaw 走最短角度并平滑 pitch；大距离重生直接跳转。仅修改显示副本，不回写服务器或本地预测。
- 复用远端渲染状态对象，去除部分每帧临时 Vector3；枪械模型缓存设为最近四种，淘汰和离页时释放 GPU 资源。
- 请求 `powerPreference:'high-performance'`，仅是浏览器提示，不保证每台电脑选择独显。

### 画质选项与 GPU 计时

大厅与 Esc 暂停页都可选，选择保存在浏览器本地：

| 模式 | 行为 |
|---|---|
| 自动（默认） | 有可靠 GPU 计时且持续过载时才逐级降低渲染分辨率；长冷却后恢复 |
| 优先流畅 | 固定像素比不高于 0.85，不改变 HUD 清晰度与逻辑 |
| 优先清晰 | 保持像素比不高于设备像素比及 1.25，不自动降档 |

自动档候选像素比为设备上限与 `1.25 / 1 / 0.85 / 0.7` 的交集。每次至少 120 个有效采样且跨越 2 秒；平均帧间隔超过 22ms 且平均 GPU 绘制超过 14ms 才降档，降档间隔至少 3 秒；恢复需低负载及至少 20 秒冷却。这是初始调优策略，不是稳定 60FPS 的承诺。

通过 `EXT_disjoint_timer_query_webgl2` 异步取样两个绘制 pass。最多四个在途查询；只在结果可用时读取，不使用 `gl.finish` 或同步 readPixels 阻塞游戏循环。GPU 时间缺失、过期、disjoint、上下文丢失时不据此降画质。无扩展设备自动档保持默认分辨率，可手动选优先流畅，避免把 CPU/显示调度卡顿误当 GPU 过载。

`window.lanStrike.getPerformance()` 提供最近最多 240 个前台绘制帧的帧间隔、CPU 动画/提交时间、GPU 最近有效时间、分辨率和模式。CPU 提交时间不是 GPU 时间，空大厅不纳入游戏帧统计。

## 真实测试结果

### 同一确定性动画工作负载

9 个远端人物 + 9 把 p_ak47 + 1 把 v_ak47；预热 120 次、测量 600 次；仅计 CPU 动画调用，不含绘制/网络。

| 实现 | CPU 中位耗时 |
|---|---:|
| 修改前 | 4.590 ms |
| 修改后 GPU 蒙皮路径 | 0.342 ms |
| 修改后保留的 CPU 参考路径 | 4.667 ms |

主线程这一部分下降 **92.56%**；不能理解为整局 FPS 提高相同比例。参考路径耗时仍接近原实现，避免用不同工作负载造成假提升。

### 正确性与浏览器

- **313 项 Node 测试通过，零失败、零跳过。** 原 CPU 路径源动画测试保留，并新增 GPU 调色板/独立法线骨、分辨率滞回、远端平滑、GPU 查询边界测试。
- Chrome SwiftShader 与默认 Apple M2 Pro/ANGLE Metal 渲染器分别完成 **132 组 CPU/GPU 像素对照**：12 外观×3 姿态×2 视角，以及 30 第一人称模型×2 源序列。每组断言有真实非背景像素；允许极小浮点边缘差异。不是两张空白图互相比对。
- 对照舞台 CPU/GPU 两路径均为 42 次绘制、17,729 个三角形；未靠减少被测模型或三角形获得成绩。
- 人物对照页全部 12 个外观、24 把第三人称武器、8 类动作通过；真实双隔离浏览器联机完成 18 项检查。
- 10 个真实本地 WebSocket 连接、单个真实 Chrome 渲染器：九个远端模型和持枪全部加载，角色存活后真实移动，隐藏战绩表不生成行、打开且数据不变时不重复重建，画质设置同步/持久化通过。软件/默认硬件渲染路径均通过。
- 购买菜单、闪光/烟雾客户端夹具、原图对照/五条通行路线、确定性调参、下坡网络与真实浏览器回归通过。测试临时服务均关闭。
- 当前 LAN 3001 服务逐字节校验七份新/改前端文件与工作区一致，实际页面加载 GPU 管线、零 Wasm 资源请求。未重启房间；已打开的页面需刷新。

### 为什么不宣称“稳定 60/120FPS”

本机自动化环境的空 rAF 对照（不计算动画、不提交绘制）平均间隔约 46.25ms，存在浏览器/显示调度节奏限制。默认硬件 10 连接短测的前台 CPU 中位约 1.7ms、GPU 最近有效绘制约 0.41ms，但 rAF 平均仍约 42.92ms。该环境不能拿来证明实体设备稳定帧率，也不能用 CPU 节省直接推导 FPS 倍数。

**未验收：** 两台实体电脑 Wi-Fi、10 台实体设备混战、长时间温控/内存、目标低配机不同画质与分辨率。此轮交付是可运行的性能优化及可靠回归，不是所有流畅度问题已消失。
