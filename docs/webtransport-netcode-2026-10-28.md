# WebTransport 与 FPS 联机体验改造

日期：2026-10-28（Asia/Shanghai）。分支：`feat/webtransport-netcode`。基线：main `394bb30`。

## 结论、目标与非目标

已接入真实浏览器原生 HTTP/3/QUIC WebTransport，不是把 WebSocket 改名；同时修改输入/ACK/重放、远端快照时间线、本地枪械反馈、有界命中回溯和诊断。目标是在抖动时减少旧数据阻塞与误纠正，让本机动作不等待往返，而不是承诺降低物理网络RTT。

初期采用独立worktree开发，不替换原3001服务，不改地图比例/碰撞/武器经济，也不引入Wasm；独立测试实例使用3002。用户后续授权已将远端main `ceca4ae` 的最新规则与本改造一起合入本地main；本次代码合并不自动推送远端或重启服务。原素材来自基线既有跟踪记录（包括 `5dfcaaf add assets`）；本次不新增、修改或宣称取得素材再分发权。

## 消息分级与边界

|消息|WebTransport|处理|
|---|---|---|
|周期状态|不可靠数据报|30Hz；只保留最新待发状态；丢弃旧序号；完整状态分片，无跨帧delta依赖|
|固定tick输入|不可靠数据报|60Hz采样；每包重复最新8条未ACK命令；序号、回合、首次副本优先|
|按键/鼠标输入边沿|额外可靠控制流|同一个输入序号，服务端与数据报副本去重，不额外模拟|
|加入、购买、切枪、换弹、取消输入、事件、计时探测|可靠双向流|控制序号/事件号去重；背压或断线时显式失败，不静默丢购买或重新建玩家|
|兼容浏览器|WSS|加入前自动回退，明确记录原因；已加入的活跃局中断线要求刷新，不无声重连|

数据报按协商大小与1000字节默认预算分片（编码上限1200字节），单消息最多64KiB、128片；重组最多8条消息、200ms过期。一条旧状态缺片不阻塞新状态。可靠消息按换行分帧、64KiB限额；服务端入站游戏消息还受8KiB、180条/秒限制。输入队列最多128条，每tick至多应用1条；等待缺口2tick，过旧输入30tick后显式跳过。ACK是“已应用或明确放弃的序号水位”，不是网络收包ACK，也不意味着每条均执行；同时保留 applied/skipped 与最后实际应用序号用于辨别。

长时间断网不保证每次按键仍能在旧回合生效；不可为了补齐旧开火/移动而无限重放或加速。可靠流断开不会恢复会话，本轮没有断线续局。状态仍是JSON全量分片，未做二进制量化、delta压缩或公网拥塞优化。

## 本机预测与输入一致性

- 同一份固定60Hz移动规则用于客户端预测与服务器模拟。服务器不采信客户端位置、dt、伤害、命中或弹药。
- 服务端按命令队列消费，ACK不再直接等于收到的最新序号；重复与乱序不重复移动/跳跃/半自动开火，空档不伪造新的按钮释放边沿。
- 客户端恢复完整权威位置、速度、地面/蹲伏/跳跃锁存，再按序重放未ACK输入。视觉误差单独平滑，远距离/换回合直接重置。
- Esc/失焦/商店通过可靠取消屏障传递当前输入水位，清理本地待处理边沿，避免迟到数据报重新激活走路或开火。
- 服务器按固定tick有界追赶，追赶后只发最新快照，不集中补发过期中间状态。

## 远端时间线

`public/snapshot-buffer.js` 将权威快照与显示副本分离，按实际服务器时间戳插值，不再单纯指数追赶最新位置。默认30Hz、自适应延迟50–160ms；延迟增长有上限、播放时间不倒退。乱序、重复、老回合与非法整包被拒绝；死亡/重生/传送/缺席成员/长缺口断开旧轨迹。

默认欠载时保持最后安全姿态，不启用无碰撞校验的速度外推。模块提供最多80ms的显式受控外推接口，但本次游戏未启用。因此极差网络下远端仍可能短暂停住，不能承诺凭空补出从未收到的动作。估计时钟含最小交付耗时，不是精确单向时延同步。

## 本地开枪与命中权威

本机枪声、枪口/武器动作、有限后坐力先本地反馈；权威shot返回按回合、输入序号、shotId去重，避免一枪两声。预测不生成命中标记、伤害、击杀、权威扣弹，也不保证服务器最终接受；死亡、换弹、菜单、空弹、冷却、武器切换均有限制。当前反馈主要覆盖枪械，刀/投掷物仍按既有权威流程。

`lag-compensation.mjs` 最多保存32帧权威目标姿态。服务器以自己发出的随机token测量应用RTT，结合受限插值延迟校验客户端视图时间，最大回溯200ms；客户端不能指定无限历史、位置或结果。仅枪械hitscan回溯目标命中盒，射手位置不回滚，地图碰撞仍阻挡射线；不整体改动实时世界，不跨回合/死亡/明显传送插值。历史不足时使用当前合法目标，不追溯刀与投掷物。现有命中盒仍是本项目近似盒，不是CS原版骨骼命中盒复刻。

## 启动与证书

```sh
npm ci
HOST=0.0.0.0 PORT=3002 npm start
# 纯HTTP/WebSocket入口，供测试兼容：
HOST=127.0.0.1 PORT=3003 npm run start:ws
```

HTTPS/WSS用TCP3002，HTTP/3用UDP3002。只在可信LAN测试；不会开放防火墙/公网转发，不要为此关闭企业安全策略。

默认本地ECDSA证书有效13天，带localhost及当前全部IPv4 SAN；启动会检查有效期和当前IP，必要时重建。证书与私钥仅在忽略目录 `.local/`，私钥0600，不修改系统信任库。显式更新：`npm run cert:local -- --renew`，后重启该测试实例。更正式的部署应使用可信HTTPS证书/域名，而不是让陌生设备盲目信任自签证书。

测试访问：`https://主机IP:3002/`。第一次浏览器可能提示本地自签证书，必须先确认地址属于这台测试Mac；不要全局禁用证书校验。WebTransport通过同源配置提供的SHA-256证书指纹绑定QUIC。该指纹不是对不可信HTML来源的额外认证，HTML本身仍需可信。Windows客户端不安装Node；优先当前Chrome/Edge，实际支持与UDP可达性以菜单显示为准。

- 默认自动模式：尝试WebTransport，加入前失败回退WSS。
- `?transport=webtransport`：强制QUIC，不以WS冒充成功。
- `?transport=websocket`：强制WSS，使用相同的新输入与插值逻辑做协议对照。
- 对局Esc → 联机诊断：显示实际transport、回退原因、插值延迟，导出连接计数、输入水位、状态到包/年龄线索和服务端回溯信息。仅本地下载，不自动上传，仍不包含昵称或完整对局。
